    About this website

    Source of the website of the Canepa Research Group, caneparesearch.org. The site is built with Jekyll and published through GitHub Pages from a separate and private repository. A HISTORY.md file in the source repository records the site’s milestones and the Cloudflare changes that git does not.

    Build the site locally

    The repository is private: ask Prof. Canepa for access, then clone it and install the dependencies (Ruby 3 and Bundler; the Jekyll version is pinned in the Gemfile):

    git clone git@github.com:caneparesearch/source-care-website.git
cd source-care-website
bundle install

    Build the site into _site/ with bundle exec jekyll build, or preview it with bundle exec jekyll serve and open http://127.0.0.1:4000/.

    A local preview runs in Jekyll’s default “development” environment, which leaves out the upgrade-insecure-requests Content-Security-Policy directive that the real, always-HTTPS site sends (update.sh builds with JEKYLL_ENV=production to turn it back on). If a local preview omits it, that is expected, not a bug — sending it locally would make the browser retry every link over HTTPS against a plain-HTTP server and fail.

    Publish

    publish.sh commits, pushes and publishes in one step:

    ./publish.sh "short description of the change" [new-file ...]

    It commits the changes to tracked files (brand-new files are only included if you name them, and .jekyll-cache/ never is), pushes the current branch, then runs update.sh with the same message. Add -n for a dry run that shows what it would do, or -y to skip the confirmation. It stops before committing if the remote has commits you do not have.

    To publish without committing anything, run update.sh yourself. It needs caneparesearch.github.io checked out next to this repository, the aws CLI with access to the carepapers bucket, and jq:

    ./update.sh "short description of the change"

    It pulls this repository, regenerates the sitemap of the paper PDFs in the bucket (update_aws_sitemap.sh, which publishes it as map.xml in the bucket itself, listed by the bucket’s robots.txt, since Google ignores a sitemap of PDFs on another host), builds the site, dates every URL in sitemap.xml by its last real edit in git (_scripts/generate-sitemap.rb; the plugin only knows the post date or the build date, commits that touch more than 30 files are ignored as repo-wide sweeps, and a renamed file keeps the dates of the edits made under its old name), makes caneparesearch.github.io match _site/ exactly (with rsync --delete; its own .git and .gitignore are kept), then commits and pushes there. It does not push this repository, so push your commits separately. A page or image deleted or renamed in this repository therefore disappears from the live site on the next publish; a renamed page keeps working through its redirect_from: entry. It refuses to deploy from a missing or nearly empty _site/, so a failed build cannot wipe the site.

    Content

    Every page is a Markdown file with a short YAML header. The date at the start of a post’s file name is its post date.

    Section Location Notes
    News news/_posts/YYYY-MM-DD-short-topic.md layout: post, category: news, title, author (first name of a team member), optional image
    Team team/_posts/ layout: member, title, position, image, and optional email, profile (the address of a university profile page), website (a personal website, shown as “Website” with a globe icon), linkedin (the name in the address linkedin.com/in/), `github`, `scholar`, `orcid`, `twitter`, `cv`, `calendar`; `alumni: true` for former members
    Research research/_posts/ layout: post, title, image
    Papers papers/_posts/ layout: paper, title, authors, journal, year, doi, image, and optionally pdf and github
    Videos videos/_posts/YYYY-MM-DD-speaker-event.md layout: video, title, author, conference, youtubeId; named like a news post, by the talk’s date, the speaker’s surname and the event, for example 2021-04-20-canepa-mrs-seattle.md

    Name a news post YYYY-MM-DD-short-topic.md: the date it was posted (with two-digit month and day), then a few lowercase words joined by hyphens that say what it is about, for example 2026-09-19-moving-to-purdue.md. The part after the date is the post’s address (/news/moving-to-purdue/), so keep it short and do not change it once the post is out. If you must rename a post, list its old address under redirect_from: in the header, as the posts renamed in September 2026 do, and pick a new name that differs by more than upper/lower case (see Team below for why). The post’s picture goes in images/news/ under the same name, .jpg for a photo and .png for a graphic or screenshot, with a .webp copy beside it (a second picture in the text adds -figure). On the News page every picture is shown in the same 3:2 frame: photos fill it, cropped from the bottom, while logos (images/misc/logo_*, any .svg) and pictures more than twice as wide as tall are shown whole inside it. Add image_fit: contain to a post’s header to show its picture whole as well, for example a logo saved as a .jpg.

    Photos and figures live in images/, in a folder named after the section.

    The pages in misc/_posts/ are linked from the footer by their title. Give one a nav_title to use a shorter label there (the About page’s footer link reads “About” while its title is “About this website”), or footer: false to leave it out (Sponsors, which is already in the navigation bar).

    Every page gets a <meta name="description"> for search results: the page’s own description field if it has one, otherwise for a paper its abstract and for a video Talk by <author> at <conference>: <title>, otherwise a post’s first paragraph, otherwise the site tagline in _config.yml, cut to 160 characters. The home page sets its own in index.html; add a description to any other page whose first paragraph makes a poor summary.

    Every page except the 404 page also gets a <link rel="canonical"> with its own address (_layouts/default.html), so search engines count variants such as /papers/?q=… or http:// as that page. The redirect pages written for old addresses (_plugins/redirect-from.rb) point theirs at the new address instead.

    Papers

    Name a paper and its files <date>-<first-author>-<journal>-<year>, all lowercase, where the journal is the ISO 4 abbreviation with hyphens, for example 2025-01-30-park-nat-mater-2025.md. If the same first author has two papers in the same journal and year, add a and b after the year. The address of a paper is built from this name, so it must be unique.

    • The image is images/papers/<name>.png, referred to in the image field.
    • The PDF is stored in the carepapers S3 bucket as <year>/<name>.pdf and is public. Set pdf: <year>/<name>.pdf; the site builds the download link from it.
    • The doi field of a preprint on arXiv (10.48550/arXiv.…) shows the arXiv icon and the label “arXiv”, and one on ChemRxiv (10.26434/chemrxiv.…) a flask icon and the label “ChemRxiv” (Academicons has no ChemRxiv logo), instead of the DOI icon.
    • The line under a paper’s title is made from authors and journal. Write authors as Surname I. I., comma-separated, with “and” before the last one (also after a comma when there are three or more) and your own name in <b>: Xie W., Deng Z., and <b>Canepa P.</b>. Write journal in ISO 4 abbreviations (except Angewandte Chemie International Edition, written Angew. Chem.) as Journal volume, pages (year) (no comma after the journal name), with the journal name in <i> and an en dash in page ranges and no issue number: <i>Chem. Mater.</i> 33, 5652–5667 (2021). Use Journal (year) while volume and pages are not known, and arXiv (year) or ChemRxiv (year) for preprints. The short reference in the lists on the home and Papers pages (First A. et al., <i>Journal</i>) is built from the same two fields by _includes/paper-ref.html, so the old ref field is no longer used. When the line under the title would wrap onto a second line, js/citation-fit.js shortens the authors to the first ones that fit plus “et al.”, always keeping Canepa P.; the full list stays in the tooltip.
    • If you rename a paper, list its old address under redirect_from: in the header (for example - /papers/old-name/) so old links keep working. _plugins/redirect-from.rb writes the redirects.
    • Keep addresses lower-case. A rename that only changes letter case (such as /team/Piero-Canepa/ to /team/piero-canepa/) cannot get a redirect_from: entry: a Mac’s disk ignores case, so the redirect page would be written over the page itself. GitHub Pages does tell the two apart, so the old address would give a 404; instead the 404 page runs js/not-found-redirect.js, which sends a visitor to the lower-case address when that page exists.
    • The search box on the Papers page (js/paper-filter.js) matches every word typed against each paper’s title, authors, journal (also by its full name, from _data/journals.yml: add a line there for a new journal), year, DOI and abstract; a full name such as “Jean-Noël Chotard” finds the author “Chotard J.-N.”, a team member is found by their name alone (“Pieremanuele”, “Tara”; give a team page aliases: for any other name people know them by, as Piero’s and Zeyu Deng’s have), and words in double quotes must appear together, as in "Chemistry of Materials". It keeps the query in the address (/papers/?q=sodium) so a filtered list can be shared. The abstracts come from papers/search.json, which Jekyll builds from the ## Abstract section of every paper and the page downloads only once the box is used, so a new paper is searchable without any extra step.

    Team

    Name a team post and its image <date>-<name>, all lowercase, matching the person’s title, for example 2020-10-25-aaron-tieu.md and images/team/2020-10-25-aaron-tieu.jpg. The address of a member’s page is built from this name, so it must be unique; sidebar links (E-mail, GitHub, Google Scholar, ORCiD, etc.) are shown alphabetically by label regardless of the order fields appear in the header.

    Write a bio in the first person. When a member leaves, set alumni: true, open the bio with a line saying where they are now (“I am now a research scientist at …”), and put finished student or postdoc periods in the past tense; hobbies and current interests stay in the present. On the Team page, current members are listed in reverse chronological order (most recently added first) and alumni alphabetically by name.

    If you rename a team page, list its old address under redirect_from: as for papers above — except when the old and new names differ only by letter case (for example fixing capitalization), since that can’t reliably redirect on a case-insensitive filesystem such as macOS’s default disk; leave redirect_from: out in that case.

    The twitter field in a team page’s header holds the X handle; the links point at x.com.

    E-mail addresses

    Never write an e-mail address in a page. Use the include instead, which prints “name [at] example.org” and lets js/email-links.js build the mailto link only while a visitor hovers, focuses or taps it, so the address is not in the page source or in the page as loaded:

    {% include email-link.html address="name@example.org" %}

    The member layout does this for the email field of a team page.

    Design

    Styles and layout

    • Styles are SCSS partials in css/, compiled into css/style.css. Layouts are in _layouts/ and shared snippets in _includes/.
    • Only the Bootstrap 5 parts the site uses are compiled in: the list of @imports at the top of css/style.scss (grid, containers, type, nav, navbar, collapse transitions, breadcrumb, helpers and utilities) replaces the full bootstrap/bootstrap.scss, which roughly halves the stylesheet. Components such as cards, buttons, forms, dropdowns and modals are left out, so a new page that uses one of them will look unstyled until its import is added there, in the same order as bootstrap.scss.
    • Long titles fade out instead of stretching their row: the News page cuts a title after two lines, and the news archive (the News page’s Index view) after four, with the top of the next line fading to show that it goes on, while the date and author below a title always show in full. Both use the fade-lines mixin in css/_variables.scss, which leaves titles whole on phones. On the Papers page a card’s title and the authors and journal line below it are never taller than the card’s picture: js/paper-titles.js measures each card and fades a longer title on its last line that fits (.is-cut in css/style.scss), and phones keep titles whole. Without JavaScript the titles fade after five lines. The preview text in the news list (.feedbox) and on the Research page (.feedboxblog) still fades at a fixed height (fade-box in css/style.scss). The home page’s Recent News and Recent papers show their two newest items in full instead.

    • The card grids show one, two or three cards a row depending on the window width, so text is not squeezed into narrow columns:

      Page Cards a row, by window width
      Papers one below 992px, two at 992–1399px, three from 1400px; 64px apart
      Team one below 768px, two at 768–1199px, three from 1200px; 30px apart
      News, Index view one below 768px, two at 768–1199px, three from 1200px; 30px apart

      The Papers page switches later than the others because each paper’s text sits beside a 120px picture: this way the text is never narrower than about 245px. Its wider gap (.paper-row in css/style.scss) keeps each title clearly closer to its own picture than to the next card’s.

    • A floating “back to top” button (js/back-to-top.js, styled as .back-to-top in css/style.scss) fades in once a page is scrolled past 600px and smooth-scrolls to the top on click (instantly if the visitor has requested reduced motion). It is added once, in _layouts/default.html’s <body>, so it applies to every page automatically; there is no per-page opt-in.
    • The footer shows, at its right edge and on the copyright’s last line, “Last update on Oct. 6, 2026 · Loaded in 0.42 s”; on phones the two wrap below the copyright.
      • The date is that of the latest commit in this repository (_plugins/last-update.rb, which also provides the ap_date filter for AP-style dates: Sept. 6, March 6), so it changes when the content does, not on every build.
      • The load time is read by js/load-time.js from the browser’s Navigation Timing API, from the start of the request to the end of the load event, so it is the visitor’s own load time, network included. It and its dot are hidden when JavaScript is off or the browser does not report the timing.
    • The mobile menu (the navbar’s button below the lg width) is opened and closed by js/nav-toggle.js, a small script that uses Bootstrap’s collapse, collapsing and show classes. The site does not load Bootstrap’s JavaScript bundle, which it needed only for this; Bootstrap’s CSS is unchanged.
    • The navbar’s magnifying glass opens a search overlay (_includes/search-dialog.html, js/search-dialog.js, styled as .search-dialog in css/style.scss): the logo and one large field across the top of the page, with the six best matches listed under it as you type and a “See all” link when there are more. Enter opens /search/?q=... with every result; Escape, the close button or a click outside closes it. The overlay and the search page share their matching (js/search-core.js), so they always find the same pages in the same order, and both give the time the search took next to the number of pages found (“7 pages in 0.4 ms”; “under 1 ms” when it is quicker than the browser’s clock can tell); the overlay downloads the search index the first time it is opened on a page. On the search page the icon focuses that page’s own field, and without JavaScript it is a plain link to /search/.
    • The X that Chrome, Edge and Safari show in a search field with text in it (which clears the field) is restyled in css/style.scss as the thin X of the overlay’s close button, in the same accent colour, instead of their grey disc. Firefox shows none.
    • Markdown tables on the About page are styled under .about-text in css/style.scss, since Bootstrap’s table styles are not compiled in: padded, top-aligned cells with a line between rows, and on phones each row stacks into a block (its first cell in bold, then the others) so the columns do not run into each other.

    Colours and accessibility

    • Colours are CSS variables defined in css/_theme.scss. The site follows the visitor’s light or dark setting, and the moon/sun button in the navigation bar switches and remembers the choice.
    • All text meets WCAG AA contrast (4.5:1) in both themes. Keep it that way when you change a colour; the navigation bar’s hover and active text uses $link-color-navlink-on-dark in css/_variables.scss for this reason. Links in running text are not underlined, since their colour already sets them apart; the exceptions are links drawn in the same colour as the surrounding text (the intro sentence on the home page, the author and DOI links in .smallnote, and the footer credits), which get a faint underline so they are not told apart by colour alone (WCAG 1.4.1). Keep that underline on any new link of this kind. Every page’s content sits in a <main> element, and icon-only links carry an aria-label (with aria-hidden="true" on the icon) so screen readers can name them.

    Fonts

    • Text is set in IBM Plex Sans, self-hosted in css/fonts/ibm-plex-sans/ with its @font-face rules in css/_plex-sans.scss: the same variable-font files and unicode-range subsets Google Fonts serves, so pages no longer wait on two connections to Google before their text can render. _layouts/default.html preloads normal-latin.woff2, the one file every page needs.

    Icons

    • Icons are Font Awesome Free 6.7.2 (fa-solid, fa-regular and fa-brands classes, for example fa-brands fa-x-twitter) and Academicons 1.9.5 (ai ai-doi), both self-hosted: the SCSS is in css/fontawesome/ and css/_academicons.scss, the fonts in css/webfonts/ and css/fonts/. The one exception is the sun of the light/dark button, a hand-drawn inline SVG in _layouts/default.html, because Font Awesome’s sun looks like a cog. Both icon fonts are trimmed to the icons the site uses: css/_icons.scss lists them, css/webfonts/ holds Font Awesome fonts cut down to those glyphs (about 5 KB instead of 300 KB) and css/fonts/academicons.woff2 the Academicons ones (3 KB instead of 128 KB); for Font Awesome, css/_icons.scss also emits only the listed icons’ classes. To use a new icon, add its name to $fa-used-icons (Font Awesome) or $ai-used-icons (Academicons) in css/_icons.scss and run python3 _scripts/subset-icon-fonts.py (needs pip install fonttools brotli); an icon that is not listed shows as a blank square. The script also updates the fingerprints in css/_icons-version.scss that are added to the fonts’ addresses; commit that file with the fonts. The full fonts it cuts from are in _fontawesome-webfonts/ and _academicons-webfonts/, which Jekyll does not publish. To upgrade Font Awesome, replace css/fontawesome/ with the new release’s scss/ and _fontawesome-webfonts/ with its webfonts/ (the .woff2 files), then run the script.
    • images/favicon/favicon.ico (and the copy at the repository root) is a multi-resolution icon (16/32/48/64px); if you replace the source artwork, regenerate it with all four sizes embedded; a single-resolution .ico renders blurry on high-DPI displays and in Windows shortcuts. images/favicon/browserconfig.xml (Windows tile icons) needs an explicit entry in _config.yml’s include: list to ship at all, since exclude: "*.xml" would otherwise drop it.

    Images

    • Photos and figures rendered through _includes/responsive-image.html (paper graphical abstracts, research/news pictures, team photos) are served as WebP with the original PNG/JPEG kept as a <picture> fallback for the rare browser or tool that cannot decode WebP; source images are never deleted, only the smaller WebP copy is added alongside. A handful of oversized news photos also get a 640px-wide WebP variant for phones, listed in _data/responsive_images.yml. Every image currently referenced this way has a WebP sibling; add one (cwebp original.png -o original.webp) whenever you add a new photo of this kind. _data/image_sizes.yml separately records each image’s pixel width/height so the include can set width/height and avoid a layout shift while it loads; regenerate an entry with sips -g pixelWidth -g pixelHeight path/to/image. Thumbnails on the listing pages (news, research, papers, team) pass loading="lazy" to the include, so browsers only fetch them once they scroll into view.

    Analytics

    • Google Analytics lives in js/analytics.js (loaded by _includes/ga.html), not inline in the page, because the Cloudflare Content-Security-Policy allows inline scripts only by hash (see Security below). It queues the page view immediately but only downloads the ~150 KB gtag.js library after the page has finished loading, so it does not slow the first paint on phones. A visitor who leaves before the page finishes loading is not counted.

    Browsers and standards

    • Supported browsers are current Chrome, Edge, Firefox, Safari and Opera. Internet Explorer is not supported (the theme relies on CSS custom properties, and Bootstrap 5 dropped it).
    • The site is checked against the W3C Nu Html Checker and the W3C CSS Validator from time to time (most recently in September 2026, across one representative page per layout and the compiled stylesheet), and issues they find are fixed — the CSS validator’s remaining messages are informational only (vendor-prefixed selectors, and CSS custom properties, which it cannot evaluate statically). This is a manual check, not part of the build or CI; there is no script for it in this repository.
    • The scripts in js/ follow JavaScript Standard Style: no semicolons, two-space indentation, const and let rather than var, and a space before a function’s parentheses. With Node.js installed, npx standard --env browser js/ checks them and npx standard --env browser --fix js/ corrects most problems itself; neither adds files to the repository. Like the W3C checks, this is run by hand when the scripts change. The one inline script, the theme switcher in _includes/theme.html, keeps its own formatting: any edit to it changes its SHA-256 hash, which the Cloudflare Content-Security-Policy must match (see Security below). Write new JavaScript as a file in js/ rather than inline, for the same reason.

    Search engines

    • robots.txt lists the sitemap, sitemap.xml (the pages, written by jekyll-sitemap and re-dated by update.sh). The sitemap of the paper PDFs, map.xml, lives in the S3 bucket and is listed by the bucket’s own robots.txt. Edit it in this repository, not in caneparesearch.github.io, whose copy is overwritten on every publish.

    Security

    • HTTPS everywhere. The custom domain (CNAME, caneparesearch.org) is served over HTTPS by GitHub Pages, with Cloudflare in front as a CDN/cache (the CSS, JS and search-index addresses end in ?v= and a fingerprint of the file, added by the fingerprint filter of _plugins/fingerprint.rb, which the templates apply to each such address, so a changed file gets a new address and is never held back by a stale Cloudflare or browser cache, while an unchanged one keeps its address and stays cached). In production, the page’s Content-Security-Policy sends upgrade-insecure-requests, so a browser retries any accidentally plain-http:// link over HTTPS instead of loading it insecurely (see “Build the site locally” above for why a local preview leaves this out). Paper PDFs in the carepapers S3 bucket are likewise only linked over https://. Cloudflare’s own SSL/TLS mode and GitHub Pages’ “Enforce HTTPS” setting are account/dashboard configuration, not files in this repository, so they aren’t documented here beyond that they’re on.
    • Content-Security-Policy and Referrer-Policy, sent as <meta> tags in _layouts/default.html: base-uri 'self' and form-action 'self' stop an injected script from changing the page’s base URL or submitting a form somewhere else; object-src 'none' blocks <object>/<embed> plugin content entirely; Referrer-Policy: strict-origin-when-cross-origin sends the full page URL as a referrer only to the same site, and just the origin (no path) to other sites.
    • Cloudflare settings (dashboard configuration, recorded here because they are not in any file):
      • Rules → Transform Rules, rule “CSP and permissions” (all requests) sets three response headers. Content-Security-Policy is stricter than the <meta> one: default-src 'self', and script-src allows the site’s own files, a few named hosts (Google Tag Manager, Altmetric, Dimensions) and inline scripts only by their exact SHA-256 hash (the theme script in _includes/theme.html is now the only one; the rule still lists a second hash, for the jQuery matchHeight call removed in September 2026, which can be deleted). Editing that inline script, or adding a new one, silently blocks it in browsers until its new hash is added to the rule, so put new JavaScript in a file under js/ instead, as js/analytics.js does. A new third-party script, stylesheet, image or API host must also be added to the matching directive. The rule also sets Permissions-Policy (camera, microphone, geolocation, payment and USB off) and Cross-Origin-Opener-Policy: same-origin.
      • SSL/TLS → Edge Certificates: HSTS on for 12 months with includeSubDomains (every subdomain must serve HTTPS; today only www, which redirects to the main site), preload off; X-Content-Type-Options: nosniff on.
      • Caching → Cache Rules: “Versioned CSS and JS, 1 year” (/css/style.css and /js/*, at Cloudflare and in browsers; safe because a changed file gets a new ?v=), and “Fonts and images, 30 days” (/css/fonts/, /css/webfonts/, /images/: 31 days in browsers, Cloudflare’s own copy follows the 10-minute origin setting). Pages keep GitHub Pages’ 10 minutes. Images keep their address when they change, so a returning visitor can see an old image for up to a month: give a replaced image a new file name. The icon fonts do not have this problem, because _scripts/subset-icon-fonts.py adds a fingerprint of them to their addresses (?v=, stored in css/_icons-version.scss), so a changed icon set gets new addresses.
    • No e-mail address ever appears in a page. See “E-mail addresses” under Content above — email-link.html prints an obfuscated “name [at] example.org” and js/email-links.js builds the real mailto: link only once a visitor hovers, focuses or taps it.
    • The members area is not an authentication system in this repository. The “Intranet” link in the footer is an outbound link to a separate Google Sites page that itself requires a Google sign-in; this codebase has no login, sessions or credentials of its own.
    • robots.txt allows every crawler (Disallow: is empty) and lists both sitemaps, so nothing on the site is meant to be hidden from search engines.

    File conventions

    .gitattributes and .editorconfig keep every text file in LF line endings, UTF-8 and ending with a newline, as POSIX defines a text file. Let your editor honour them, and do not save files with CRLF endings or without a final newline. The one exception is google736838dc293297e8.html, the Google Search Console verification file, which must stay exactly as Google issued it.
